# AGENTS.md — ar-h (AR «фигуры и руки»)

Рабочий документ проекта. Чат-сессия не является источником истины — источник истины здесь и
в исходниках `ar/`.

## Что за проект

Passthrough-**AR**: пять цветных фигур (сфера, куб, тетраэдр, додекаэдр, тор), которые толкают
**реальные руки** (hand tracking, без контроллеров). Направление удара — по нормали в точке
касания (бильярд), инерции нет: рука встала — фигура встала. Фигуры толкают и **друг друга** по
той же схеме, что и руки. Движок — three.js **r128** (UMD).

Поставка **многофайловая**: страница + соседние скрипты, никакой сборки и единого архива.
Требования «один самодостаточный файл» больше нет (2026-11-04).

## Как устроена физика (имя модуля старше идеи)

`create()` даёт **мир**: конфиг + `world.bodies[]`. Тело = шар-прокси
(`pos/vel/anchor/radius/contacts`). Первое тело — сфера, и `world.pos`/`world.vel`/
`world.contacts` это оно же (историческое одно-телевое API, на нём висят тесты). Остальные
фигуры добавляет `addBody(world, {id, radius})`; `place`/`speed` принимают и мир, и тело.

Шаг (`step(world, dt, joints)`) общий для рук и фигур: контакты собираются и с суставами, и с
соседними телами; нормаль — линия центров; скорость тела = его фактическое перемещение / dt,
ограниченная скоростью того, кто толкает. Ключевое правило взаимодействия тел: **тело, которое
в этом кадре ведёт рука, для соседа неподвижно** (как сама рука), поэтому сфера, ведомая рукой,
ведёт куб целиком, а не делит с ним перекрытие. Если ведёт рука обе фигуры (или ни одной) —
перекрытие делится пополам.

## Коллизии и движение: выбор — Jolt Physics (решено 2026-11-04)

Дальше физика переезжает на **`jolt-physics` 1.1.1** (MIT; релиз npm 2026-10-23; C++-первоисточник
`jrouwe/JoltPhysics` — 12.2k звёзд, push 2026-11-03, 14 открытых issue). JS-интерфейс повторяет
C++-интерфейс, документация общая. Причина переезда: честные формы вместо шаров-прокси (см. «Бублик»
ниже) и настоящий поворот с моментом; требование «инерции нет» к тому моменту уже снято.

Почему не остальные — замеры 2026-11-04 по npm/GitHub, а не по памяти:

| библиотека | лицензия | gzip | статус |
|---|---|---|---|
| **Jolt** (`jolt-physics`) | MIT (SPDX-заголовок прямо внутри бандла) | 888 КБ `wasm-compat`; 132 + 727 КБ `wasm`+`.wasm` | релиз 2026-10-23, активен |
| Rapier 0.21.0 | Apache-2.0 (одна, не dual) | 1 614 КБ compat / ~1 190 КБ wasm | 2026-09-25, активен. Второй кандидат; Apache ⇒ нужен `NOTICE` и пометки изменений |
| cannon-es 0.20.0 | MIT | 72 КБ | **заморожен**: релиз 2022-08-12, последний push 2024-01-06 |
| three-mesh-bvh 0.9.18 | MIT | 61 КБ (UMD есть) | с **three r128 несовместим**: peer `three >= 0.159`, бандл импортирует `BatchedMesh`, которого в вендоре нет; для r128 годится только ветка 0.5.21 (2023) |

По cannon-es отдельно, чтобы не наступиться позже: реализованные пары Narrowphase —
`sphereSphere/Plane/Box/Convex/Trimesh/Heightfield/Particle`, `boxBox/Convex/Heightfield/Particle`,
`convexConvex/Trimesh/Heightfield/Particle`, `planeBox/Convex/Particle/Trimesh`, `particleCylinder`,
`heightfieldCylinder`. Итого `trimesh↔trimesh` нет, а `Cylinder` сталкивается только с `Particle` и
`Heightfield`.

### Как заводится (проверено по официальным примерам и `types.d.ts`)

- пакет — ESM (`"type": "module"`): `import initJolt from '…/jolt-physics.wasm-compat.js'`,
  `initJolt().then(Jolt => …)`. Странице поэтому нужен `<script type="module">`; прежняя связка
  классических `<script src>` для Jolt не работает (three и физический модуль остаются как были).
- варианты сборки: `wasm-compat` (wasm зашит base64, 3.16 МБ raw / 888 КБ gzip, один файл, без
  `fetch` — начинать с него, раскладка без сборки сохраняется), `wasm` (947 КБ JS + 1.98 МБ `.wasm`,
  нужен `fetch` по HTTPS), `asm` (5.35 МБ чистого JS, wasm не нужен вовсе).
- проверенные имена API (переписано 2026-11-04 после spike-прогона — прежний абзац был
  выдуман из C++-доков и оказался неверен): **у `PhysicsSystem` нет ни конструктора, ни
  `Update`** — точка входа `Jolt.JoltSettings` → `new Jolt.JoltInterface(st)` →
  `ji.GetPhysicsSystem()` / `ps.GetBodyInterfaceNoLock()`, шаг — `ji.Step(dt, collisionSteps)`.
  `JoltSettings` обязан получить все три фильтра (`mBroadPhaseLayerInterface`,
  `mObjectVsBroadPhaseLayerFilter`, `mObjectLayerPairFilter`), иначе `Aborted`. Дальше —
  `CreateAndAddBody(new Jolt.BodyCreationSettings(shape, pos, rot, Jolt.EMotionType_…,
  layer), Jolt.EActivate_Activate)`, `SetPositionAndRotation`, `SetLinearVelocity`,
  `SetAngularVelocity`, `SetMaxLinearVelocity`, `SetMaxAngularVelocity`, `GetShape`,
  `GetCenterOfMassTransform`, `RemoveBody` + `DestroyBody`.
  **`SetKinematicTarget` в JS-биндинге нет** — кинематическому телу ставят СКОРОСТЬ
  (`SetLinearVelocity`), и одну только скорость: кинематика сама интегрирует её за шаг,
  а позиция+скорость = двойной шаг с накопным дрейфом.
- грабли embind (все стоят в `ar/jolt/spike.mjs` как проверки):
  - `ObjectLayerPairFilterTable` создаётся с **запрещёнными** парами — без явных
    `EnableCollision(a,b)` коллизий нет вообще, и молча;
  - **мир один на процесс/страницу**: второй `JoltInterface` = `Aborted(OOM)`; «сбросить
    мир» = удалить тела (`RemoveBody` + `DestroyBody`);
  - `CreateAndAddBody` отдаёт `BodyID` как **общее временное окно**: второй вызов затирает
    первый, у двух тел становится один id → `Aborted` в `DestroyBody`. Хранить копией:
    `new Jolt.BodyID(id.GetIndexAndSequenceNumber())`;
  - `GetPosition()` (`RVec3`) — то же окно: числа снимать сразу;
  - методы `ContactListenerJS` обязаны быть **собственными свойствами** инстанса
    (проверка через `hasOwnProperty`), а не методами прототипа; в колбэках приходят
    указатели на `Body` (числа) → `Jolt.wrapPointer(ptr, Jolt.Body)` /
    `Jolt.wrapPointer(mp, Jolt.ContactManifold)`; константа — `Jolt.ValidateResult_AcceptContact`
    (без буквы `E`);
  - `ShapeSettings` / `ShapeResult` / `Shape` надо держать в JS-массиве, иначе wasm-память
    освобождается и тела ходят по мусору;
  - `mConvexRadius` у `BoxShapeSettings` по умолчанию ненулевой и **съедает рёбра и углы**
    (ребро куба давалось на 22 мм позже, угол — на 40 мм). Ставить 0 у всех convex-форм.
- `jolt-physics` **заводится в node** (1.1.1, `mMaxWorkerThreads = 0`) — принцип «физику
  гонять без браузера» на Jolt выжил.

### Бублик: методология, чтобы он работал как ожидается

Причина нынешнего поведения: у тела один шар-прокси `radius`, нормаль = линия центров, поэтому
отталкивание начинается в 0.107 м от центра бублика при реальной стенке отверстия в 0.045 м — палец
не доходит до дырки ~6 см. Ошибки по остальным фигурам: грань куба −25 мм, грань тетраэдра −42 мм,
додекаэдр ±10 мм.

**В Jolt примитива тора нет** — в `types.d.ts` (весь экспортируемый API, 202 КБ) слово `torus` не
встречается ни разу. Тора нет и в cannon-es, и в Rapier: это не особенность Jolt, тор собирается из
выпуклых детей везде.

Способ: **`StaticCompoundShapeSettings` + `CapsuleShapeSettings` по кольцу** (как в официальном
примере: `AddShape(new Jolt.Vec3(x, 0, 0), Jolt.Quat.prototype.sIdentity(), settings)`).

- дети compound'а обязаны быть выпуклыми — капсула и сфера подходят, `MeshShape` для движущегося тела
  не подходит (в Jolt mesh только для static/kinematic; проверить при первом запуске);
- для `TorusGeometry(R = 0.075, tube r = 0.03)`: N капсул радиуса 0.03, их оси — хорды окружности
  радиуса 0.075. В spike середина хорды стоит на самой окружности (`half = R·sin(π/N)`, поворот
  `Quat.prototype.sRotation(V(0,0,1), a)` — у капсулы ось local +Y), соседние капсулы смыкаются
  концами;
- измерено (2026-11-04): **стенка дырки встала ровно на R − r = 0.0450**, сагитта полигона
  (1.43 мм при N=16) уходит наружу кольца, а не в дырку — N=16 и N=32 дают одну и ту же дырку.
  Прежняя формулировка «многоугольник вписан ⇒ дырка шире» неверна: при такой раскладке
  многоугольник описан вокруг середины хорды;
- `R` и `r` должны жить в одном месте и идти и в `TorusGeometry`, и в compound — иначе физика и
  картинка разъедутся;
- тензор инерции Jolt считает сам из compound'а (`GetMassProperties`), поэтому корректный поворот
  бублика достаётся бесплатно — в прежней модели момента не было вовсе (замер: m = 3.1334,
  Izz = 0.019652, поворот 1.63 рад за 1 с при заданных 2 рад/с).

### Spike на Jolt: замеры (2026-11-04, `node ar/jolt/spike.mjs`, 21/21)

Эталон = чистая геометрия; «истина» считается как `граница_формы + радиус_пальца + handPad`
(контакт начинается на расстоянии speculative).

| что | старая физика (шар-прокси) | Jolt | истина |
|---|---|---|---|
| палец в дырке бублика | контакт с \|z\| < 0.109, не проходит | проскочил насквозь, контактов 0 | — |
| касание материала бублика по экватору | 0.109+ | 0.1240 | 0.1240 |
| размер дырки глазами физики | — | 0.0450 | 0.0450 |
| грань куба (BoxGeometry 0.13) | 0.1090 | 0.0830 | 0.0840 |
| ребро куба | 0.1090 | 0.1080 | 0.1109 |
| угол куба | 0.1090 | 0.1300 | 0.1316 |
| зазор палец↔бублик при толкании | — | 0.1174 | 0.1160 |
| скорость фигуры при пальце 0.4 м/с | — | 0.400 | 0.400 |

- `PhysicsSettings.mSpeculativeContactDistance` по умолчанию **0.02** — то есть контакты
  по умолчанию начинаются за 2 см до касания, ровно тот баг, ради которого переезд. Здесь
  живёт `handPad`: ставить 0.008 и сверять зазоры с этим числом. `mPenetrationSlop` тоже 0.02.
- контактов **static↔kinematic и kinematic↔kinematic нет вовсе** — геометрические пробы
  делать динамическим пришпиленным телом (`SetPositionAndRotation` + обнуление скоростей
  каждый кадр).
- `WereBodiesInContact` отвечает только «была ли пара в контакте»; глубины и точек нет.
  Предикат контактов и точки касания для страницы — манifold'ы `ContactListenerJS`
  (`get_mPenetrationDepth`, `GetWorldSpaceContactPointOn1`).
- Остаточные расхождения: грань −1 мм, ребро −3 мм, угол −1.6 мм, зазор у бублика +1.4 мм —
  это один шаг свипа (0.001 м) и `mPenetrationSlop`; для пальцев (типы 9–15 мм) незначимо.

### Spike-страница на Jolt: что проверено в браузере (2026-11-04, `node ar/jolt/page-test.mjs`, 12/12)

`ar-jolt.html` + `ar/jolt/spike-page.js`: та же физика, что в node, только в three и в браузере.
Числа совпали с node-спайком один в один: экваториальное касание бублика 0.1240 (истина 0.1240),
зазор при толкании 0.1174 (истина 0.1160), скорость бублика 0.400 при пальце 0.400, сквозь
отверстие — ноль контактов, палец прошёл ровно через центр (0.0000 м). Скриншоты:
`/tmp/arhands/jolt_start.png`, `jolt_hole.png` (палец в дырке).

Грабли, из-за которых страница сначала была чёрной (все три — про проверку headless, не про Jolt):

- **ES-модуль из `file://` Chrome не грузит** (CORS, opaque origin). Тест обязан поднимать
  http-сервер и гонять страницу по `http://127.0.0.1:…`. Сервер живёт в том же процессе, что
  и Chrome, поэтому запускать chrome надо `execFile` + `await`: синхронный `execFileSync`
  блокирует event loop, сервер не отвечает, и оба ждут друг друга до бесконечности.
- **В режиме `--dump-dom` `requestAnimationFrame` не вызывается ни разу** (`frames: 0`).
  Первый кадр страница рисует явно сразу после сборки сцены, а тест читает пиксели сам:
  `gl.readPixels` сразу после `renderer.render()` в том же таске (`preserveDrawingBuffer:false`,
  а декодирование data-URL через `Image` до дампа не доживает).
- **`Group.lookAt` разворачивает к цели +Z, а не −Z как камеру.** Долли (`Group` с камерой,
  см. «Как разрабатывать VR-приложения») с `dolly.lookAt(0,0,0)` ставит камеру СМОТРЕТЬ ОТ сцены:
  всё за камерой → three не делает ни одного draw call (`info.render.calls = 0`,
  `memory.geometries = 0`), скриншот чёрный, исключений нет. Долли на +Z от мира должен иметь
  почти единичный поворот (только лёгкий наклон по X), а не lookAt.
- Диагностический хук `window.__js.diag()` — то, чем это нашлось: `calls/tris/frames/ctxLost/errs` +
  мировые матрицы камеры и объектов. Чёрный кадр сам по себе по-прежнему ни о чём не говорит.

### Руки, слои, перенос нынешних правил

- Руки: **50 кинематических сфер** (25 суставов × 2 кисти, `EMotionType_Kinematic`), радиус =
  `XRJointPose.radius` с тем же clamp, что сейчас (`minJointR 0.004` / `maxJointR 0.03`), за кадр —
  `SetLinearVelocity(id, (цель − позиция)/dt)` и **ничего больше** (`SetKinematicTarget` нет;
  позиция+скорость дают двойной шаг, а без скорости палец проваливается в фигуру на ~25 мм).
- Слои обязательны: Jolt требует broadphase/narrowphase слои и фильтр пар. **рука↔рука выключена**
  (иначе 50 суставов начнут расталкивать друг друга), рука↔фигура включена, фигура↔фигура включена.
- «Инерции нет» снято владельцем 2026-11-04: правило ввели только чтобы шар не улетел за границы во
  время теста. Динамика Jolt разрешена, а границы остаются прикладными: `maxSpeed 2.5` →
  `SetMaxLinearVelocity` (+ завести `SetMaxAngularVelocity`), `leash 2.2` → в коде страницы (аналога
  в Jolt нет: пружина через `AddForce` к `anchor` либо позиционный кламп), пол `floorY` →
  static-плоскость.
- `handPad 0.008` / `bodySkin 0.002` (запас до касания) → `PhysicsSettings.mSpeculativeContactDistance`
  (по умолчанию 0.02 — его и ставить в 0.008; работает и для рука↔фигура, и для фигура↔фигура);
  `tangentialGain` → `mFriction`; `releaseDamping` → линейный и угловой damping.
- Размер формы: Jolt не масштабирует форму трансформом тела → любой рост/сжатие = новая форма через
  `SetShape(…)` с пересборкой compound'а. Равномерный масштаб тривиален, неравномерный — новые
  радиусы капсул.

## Найденное про hand tracking в WebXR (проверено по спекам/MDN/исходникам, 2026-10-29)

- `requestSession('immersive-ar', {optionalFeatures:['local-floor','hand-tracking','dom-overlay'],
  domOverlay:{root:hud}})`. `isSessionSupported` НЕ принимает фичи — hand-tracking без открытия
  сессии не проверить; реальный состав фич читаем из `session.enabledFeatures`.
- `XRHand` = 25 суставов в фиксированном порядке спеки (`wrist`, затем по 4/5 на палец, у
  большого нет `*-phalanx-intermediate`), обход `for (const [name, space] of hand)`.
  Поза — `frame.getJointPose(space, refSpace)` → `transform` + `radius` (радиус сустава в
  метрах — готовый радиус коллизии). `getJointAngles`/`jointAxes` в спеке НЕТ.
  Оси: `-Z` вдоль кости к кончикам, `-Y` из ладони наружу.
- `frame.fillPoses(hand.values(), refSpace, Float32Array(16*25))` + `fillJointRadii` — быстрый
  путь без аллокаций, НО отказывает на всю кисть, если не оттрекан хоть один сустав ⇒ нужен
  запасной путь поштучный (в `app.js` есть).
- Порядок `inputSources` не гарантирован, поэтому базовый слот (0 / 25) вешается на сам объект
  `XRInputSource` через `Map`, а пропавшая рука заливается NaN — иначе скорость сустава
  считается через «телепорт».
- `local-floor` в `immersive-ar` законен, но всегда требует согласия: просим optional и при
  отказе `setSession` падаем на `local` (тогда без пола).
- `renderer.xr.getReferenceSpace()` в r128 отдаёт ТУ ЖЕ систему отсчёта, что и рендер ⇒ позы
  суставов можно класть в позицию объекта сцены напрямую.
- Passthrough требует `new THREE.WebGLRenderer({alpha:true})` и `scene.background = null`
  (Color-фон ставит clear alpha = 1 и гасит камеру).
- `dom-overlay` на Quest не подтверждён: проверять `session.domOverlayState`, а управления
  дублировать жестами — `select` (щипок) и `squeeze` (кулак) на самой сессии.

## Как разрабатывать VR-приложения: three.js r128 + WebXR

- UMD-сборка r128 **не содержит** `VRButton` (он только в `examples/jsm`), нет
  `xr.setFoveation` (r131) и `xr.cameraAutoUpdate` (r129) → кнопка входа в VR своя.
- `renderer.xr.enabled=true` обязателен, иначе `render()` игнорирует XR.
  `xr.setSession()` в r128 **async** — ошибки ловить через `.then(a,b)`.
- Поза головы пишется в `camera.matrix` **относительно родителя камеры** ⇒ нужен долли
  (`Group` с камерой); `camera.position` в XR = положение в системе отсчёта комнаты, а не в
  мире. Контроллеры/хват тоже вешать на долли: их позы выдаются в системе отсчёта комнаты.
  `getController(i)` создавать ДО `setSession`, иначе события не привязываются к индексу;
  `event.data` — это `XRInputSource`; `matrixWorld` контроллера в кадре — на 1 кадр старше.
- `setReferenceSpaceType('local-floor')`, держать `local-floor` в `optionalFeatures` + фолбэк
  на `local` (при падении на `local` руками добавлять поправку на рост глаз, ~1.6 м).
- `setSize`/`setPixelRatio` во время сессии — no-op (с предупреждением); после выхода размер
  холста и `camera.aspect` восстанавливать вручную; `resize`-хэндлер guard'ить
  `if (renderer.xr.isPresenting) return;`.
- `near/far` камеры уходят в `depthNear/depthFar` со сдвигом в один кадр — не анимировать.
- Рендер-таргеты внутри XR-кадра портят картинку (до r133 слой байпассит bind-кэш);
  `shadowMap` работает, тень считается один раз за кадр. `antialias` слоя XR наследуется
  от конструктора рендерера.
- **xr-standard mapping** (источники: webxr-gamepads-module, реестр input-profiles):
  `axes[2]/[3]` — стик (у Quest `axes[0]/[1]` — нули), `axes[0]/[1]` — тачпад;
  кнопки: `0` trigger (аналог в `.value`), `1` squeeze, `2` клик тачпада, `3` клик стика,
  `4` A/X, `5` B/Y. Знак: положительное = вправо/вниз ⇒ «вперёд» = `-axes[3]`.
- Опрос контроллеров — `session.inputSources` (у `XRFrame` своего `inputSources` НЕТ);
  `Gamepad` мутируется на месте, события кнопок считать самому по прежнему состоянию.
- `dom-overlay` для `immersive-vr` фактически недоступен (AR-only) → интерфейс в сцену
  (CanvasTexture-панели: запястье, лист помощи, тост).
- Нужен защищённый контекст (`https://` или `localhost`); во фрейме —
  `allow="xr-spatial-tracking"`, иначе `SecurityError`. `isSessionSupported` не должен
  показывать промптов; `requestSession` — только из обработчика клика.

## Как проверять WebXR без шлема (переносимые грабли)

1. **SwiftShader рендерит ~1 кадр за секунды** → `clock.getDelta()` непригоден. В тестах
   `renderer.render=function(){}`, часы заменяются на `getDelta()===1/60`, кадры шагаются
   вручную (`__hs.step(n)`).
2. **Для скриншотов так нельзя**: `preserveDrawingBuffer:false`, поэтому кадр, отрисованный
   вне реального rAF, на снимке чёрный. Съёмка — только боевым циклом rAF.
3. **Код внутри IIFE**: скрипт, дописанный перед `</body>`, не видит внутренние переменные —
   поэтому наружу заранее экспортируется `window.__hs` (`world`, `bodies`, `body(id)`,
   `park(x,y,z)`, `info()`, `step(n, fill)`, `cfg()`, `setMode()`), и тесты работают только
   через него. `info()` отдаёт и пофигурный список `bodies:[{id,x,y,z,r,speed,contacts}]`,
   и `bodyPen` — самое глубокое взаимное проникновение тел (после шага обязано быть ~0).
   `park()` уводит лишние фигуры из кадра теста, чтобы их контакты не мешали проверяемой паре.
4. Живые обработчики висят на `document` → события шлёт на `document` c `bubbles:true`
   (в `page-test.mjs` это `PointerEvent` на canvas с `bubbles:true`).
5. У синтетического `mousemove` `movementX=0` — годится только запасной путь обзора/курсора по
   `clientX/clientY`.
6. Иммерсивную сессию headless-Chrome не даёт (`navigator.xr.isSessionSupported` → false).
   Логику проверяют на **фейковой** сессии: объект `{inputSources:[{handedness,
   gamepad:{axes,buttons}}]}` в замыкаемую переменную сессии + `renderer.xr.isPresenting=true`,
   `connected` на контроллерах вызывается вручную. Покрывает игровую логику, но НЕ реальный
   XR-слой — живой тест на шлеме обязателен. Здесь вместо фейковой сессии физику гоняют через
   `__hs.setMode('none')` + `__hs.step(n, fillFn)`: руки задаются массивом `x,y,z,r` на сустав.

## Известные ограничения (не баги)

- Перетаскивания/хвата нет — только выталкивание (просили именно его).
- Все тела сталкиваются как **шары-прокси**: у куба, тетраэдра, додекаэдра и тора один
  `radius` (между вписанной и описанной сферой), поэтому угол куба и отверстие тора физика
  не различает. Это **снимается переездом на Jolt** (см. «Коллизии и движение: выбор — Jolt
  Physics») — в текущем модуле честных граней нет и добавлять их не планируется.
- Фигуры только перемещаются, но не вращаются: момента в модели нет, позиционная коррекция
  даёт чистый перенос. Тоже снимается переездом: Jolt считает инерцию по форме сам.
- При двустороннем сжатии двумя руками перекрытие геометрии неизбежно: фигура встаёт
  посередине.
- В шлеме без `dom-overlay` интерфейс — только жесты.
